# Design decisions: APC 2026 → VHA rules (full run)

Judgment calls made in setting up the full run (Claude, for Tony's review). Calls made inside
builds and checks are recorded per condition and per element in the provenance, reconcile and
checker files. Follows the pilot (`../apc-2026-pilot-20261101/DECISIONS.md`) and the build plan in
`../review-page-handoff-20261101.md`, except where noted.

| Decision | Kind | Chosen | Alternatives | Why |
|---|---|---|---|---|
| Scope | inference | The 83 APC 2026 pages with a clinical red box (84 found by the red-border test, minus p6, the alphabetical index) | Every page with diagnostic wording (~168); red boxes only on pages with a 2023 rule | The team's stated scope and the build plan's next step ("all red-box pages") |
| Standard | inference | Will's PR #1310 briefing, gold standard 2023 p20, his six test constraints | The pilot's house-style examples | It is VHA's own target for every page; it fixes the pilot's flowchart weakness (image first, flowchart file first) |
| Builders blind to Will's 2023 rules | inference | Yes, except the gold standard (2023 p20 = 2026 p28 anaphylaxis), which every builder gets as the model, in its PR #1310 revision | Migrate from the 2023 rules | Same independence as the pilot, so the comparison with Will's rules measures something; Will names the gold standard as required reading |
| Vocabulary | inference | All 491 terms in VHA's current rules, without page attribution | Excluding each page's own file (pilot) | Every page is now in scope, so exclusion is impossible; terms without pages leak little and reduce drift (the pilot's Obstipation/Constipation) |
| Two builds per page | deterministic + inference | Two separate builders (same briefing, gold standard and vocabulary), code diff, one reconciler who records a choice and reason per difference | One build | The pilot showed one build is not reproducible (4 of ~10 conditions differed on an identical page) |
| Triple review | inference | 3 forward + 3 backward checkers per page, instructed to work blind to each other, the builders' notes and the reconcile record (not enforced; rules-to-page checkers see each condition's cited element and quote); mixed models | 1 each way (pilot); rounds with fixes between | "Triple reviewed backwards and forwards" (Tony); independent agreement is the signal, disagreement goes to a person |
| SNOMED reference | deterministic | Own copy of VHA's lookup rule, from the 2025-12-01 RF2 zip: active FSN of active concept, split into name + tag, exact match (`tools/build_snomed_db.py`) | VHA's Postgres via the app's MCP (needs Docker) | Same rule as `03_snomed_inferred.ts` + `conceptDoesNotExist`; reproduces the known failures (Inhalation injury, Alcohol withdrawal, Eyelid, Chest structure); works without Docker. Since confirmed at load by Will's test's SNOMED steps against VHA's database, except 79 concepts the test doesn't reach (77 body structures, mostly finding sites, plus 1 attribute and 1 substance) |
| Concepts checked | deterministic | Every concept in the parsed tree, including `finding_site` values | VHA's `allConceptsToLookFor` only | That function skips finding-site body structures, which is why Will's "Eyelid" and "Chest structure" pass VHA's test but cannot resolve. Flagged per concept |
| Condition list for provenance | deterministic | Canonical strings from VHA's `inverseSExpression`, walking `and/or/any2/not`, keeping onset comparisons (`tools/gate.ts`) | Pilot's Python parser | Review-page handoff known issue: the Python parser missed `diagnosis` and negation |
| Element ids | deterministic | Positional `id` for reading, content-hash `key` for citing | Positional only | Handoff known issue: positional ids re-point every citation when the extractor changes |
| Box headers | deterministic | Headers are elements; triggers cite them | Cite the first criterion (pilot) | Pilot bug: "Hb < 6" cited for "pallor" |
| Criteria in one bullet | deterministic | Not split; a criterion is (element key, verbatim quote) | A splitting rule (handoff) | Splitting heuristics would mis-split; the quote already identifies the criterion |
| Shock | inference | Encode "Shock/SBP < 80" as each page writes it; no shared definition | One shared definition (the shock-definition question in the findings log) | Not ours to decide; flagged per page for the reviewer |
| E-book vs Summary of Changes | inference | E-book wins (builders don't see the summary) | Summary | The e-book is the published guide; disagreements (burns fluids) are in the findings log |
| Pointer-only boxes (p14, 15, 83–87, 93) | inference | Pointer elements `cross_reference_only`; the rest of the page is encoded as usual. Only p181, where nothing is representable, ended up as a comment-only `.lisp` | Skip the page | Every red-box page is accounted for |
| File naming | inference | 2026 page number + manifest slug | 2023 numbers | The rule set is the 2026 edition |
| Where the rule set lives | inference | `ruleset/apc-adult-2026/` in this repo (built in `build/final/`); checked against a private build copy of VHA (`~/Developer/vha-build`, push disabled) | A branch in the team repo | At build time, nothing went to the VHA repo. Since 2026-11-05, at Will's request, the set also goes to a VHA branch (from `main` `6e2cc0e82` with PR #1310 merged), replacing `s_expression/rules/apc-adult/`; see `docs/apc-2026-conversion.md` there |
| `(no X)` round-trip bug in VHA | deterministic | `load_into_vha.sh` patches `inverseSExpression` in the private build copy for the load only and reverts it on exit | Rewrite rules to avoid `(no X)`; leave the set unloadable | One-line VHA bug (findings log); changing clinical logic to dodge a bug is wrong, and the gate needs the unpatched file |
| Measure-task items in Will's test | deterministic | Gate counts them as checked for and lists each use in `vha_test_differences`; the loader excuses them in Will's test only when run with `--waive` (by default it excuses nothing, since 2026-11-05) | Add check_for tasks for every measured value | His test has a TODO for exactly this |
| `(no X)` evidence in Will's constraints | inference | The gate counts a check for X as covering `(no X)` evidence in the probable-diagnosis and priority-evaluation constraints | Exact s-expression matching, as Will's briefing and test do | Will's test itself says a rule keying off a finding's absence still relies on having checked for it; his test flags 146 such cases; they are listed for Will to decide |
| Onset subjects in Will's constraints | inference | The gate counts the subject of an onset comparison as evidence | Not counting it, as VHA's `allEvidenceToLookFor` does | The briefing documents onset in `due_to` positions; his test flags 15 such cases; they are listed for Will to decide |
